# СМС Центр (smsc.ru) в кабинете брокера

Подключено 24.09.2026. Решение владельца: **пока отправляем только четыре
согласованных текста**, каждый в одну часть (до 70 знаков), отправитель
`St. Michael` (на регистрации у операторов), телефоны клиентов в СМС не попадают.

| Вид (`kind`) | Когда | Текст |
| --- | --- | --- |
| `LOGIN_CODE` | «Войти по коду из СМС» на странице входа | `Код входа в кабинет брокера: 482913. Никому не сообщайте.` |
| `REGISTER_CODE` | подтверждение номера при регистрации | `Код подтверждения номера: 482913. Действует 10 минут.` |
| `PASSWORD_RESET_CODE` | «По СМС» на восстановлении пароля | `Код для смены пароля: 482913. Если это не вы — не вводите его.` |
| `FIXATION_EXPIRY` | за 7, 3 и 1 день до конца уникальности (крон 09:00) | `Закрепление клиента Иванов А. истекает 20.10. Продлить — в кабинете.` |

## Разделение

- **Кабинет**: рождает 6-значный код (`crypto.randomInt`), хранит только хеш
  (SHA-256 с «перцем» `OTP_PEPPER`/`JWT_SECRET` и id записи), срок 10 минут,
  одно назначение — один код, 5 попыток ввода, лимиты выдачи (раз в минуту и
  5 в час на номер; 10 в час и 30 в сутки на IP), журнал отправок и статусов.
- **СМС Центр**: аккаунт, баланс, имя отправителя, доставка и отчёт о ней.
  Встроенная услуга «код с проверкой» не используется.

## Где что лежит

- `packages/integrations/src/smsc.adapter.ts` — HTTP API smsc.ru (`send.php`,
  `status.php`, `balance.php`, JSON `fmt=3`; в `psw` — API-ключ).
- `apps/api/src/sms/` — `sms-templates.ts` (тексты), `sms.service.ts`
  (настройки, отправка с журналом `sms_messages`, статусы доставки, тест),
  `otp.service.ts` (коды `phone_otps`, лимиты, проверка).
- `apps/api/src/auth/` — `GET /auth/sms-options`, `POST /auth/otp/request`,
  `POST /auth/otp/login`, `POST /auth/otp/reset-password`; регистрация
  принимает `smsCode`, когда подтверждение включено.
- `apps/api/src/notification/notification.processor.ts` — канал `SMS` уходит
  **только** с `smsKind` из утверждённого списка; старые постановки в очередь
  (с телефонами клиентов в тексте) пропускаются.
- `apps/api/src/scheduler/scheduler.service.ts` — напоминания об истечении
  (текст `fixationExpiryText`) и опрос статусов доставки каждые 10 минут.
- Админка → **Интеграции**: доступы, флаги, баланс, тест, журнал (`/admin/sms/*`).
- Веб: `apps/web/src/components/SmsCodeField.tsx`, страницы входа,
  регистрации и восстановления пароля показывают СМС-вариант только если он
  включён (`/api/auth/sms-options`).

## Настройки (SystemSetting, приоритет над env)

| Ключ | Значение |
| --- | --- |
| `SMSC_LOGIN` | логин аккаунта smsc.ru (`stmichael`) |
| `SMSC_API_KEY` | API-ключ HTTP/S (секрет; в UI видны последние символы) |
| `SMSC_SENDER` | имя отправителя; пусто — по умолчанию аккаунта (пока имя на подключении) |
| `SMS_ENABLED` | `1` — общий выключатель; по умолчанию выключено |
| `SMS_OTP_LOGIN`, `SMS_OTP_REGISTER`, `SMS_OTP_PASSWORD_RESET`, `SMS_FIXATION_EXPIRY` | `1` — включить вид |

Env-fallback: те же имена в GitHub Secrets → `deploy.yml` → `.env` сервера →
`docker-compose.yml`. Тестовая отправка из админки не зависит от `SMS_ENABLED`.

## План включения

1. После деплоя: в «Интеграциях» нажать «Проверить баланс», отправить четыре
   теста на номер Андрея.
2. Включить `SMS_ENABLED=1`, `SMS_OTP_LOGIN=1`, `SMS_OTP_REGISTER=1`; неделю
   смотреть журнал (доставка, цена).
3. Затем `SMS_OTP_PASSWORD_RESET=1` и `SMS_FIXATION_EXPIRY=1`.
4. Когда операторы зарегистрируют имя — заполнить `SMSC_SENDER`.

## Журнал

`sms_messages`: кому, вид, текст (код заменён на `••••••`), статус
(`QUEUED → SENT → DELIVERED | FAILED`, `SKIPPED` — вид выключен), id у СМС
Центра, цена, ошибка. Статусы доставки подтягиваются 48 часов.
