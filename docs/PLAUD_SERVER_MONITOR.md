## Расписание и результат

- `plaud-name-monitor.timer`: ежедневно **09:00 МСК**, окно последних 7 дней.
- `plaud-name-monitor-watchdog.timer`: **09:15 МСК**, проверяет результат и
  подтверждения Telegram без повторного чтения записей. При проблеме — отдельное уведомление.
- После простоя `Persistent=true` выполняет пропущенный запуск. Запуск таймера
  не означает мгновенную доставку: PLAUD и Telegram требуют сетевых запросов.
- Успех — успешное чтение PLAUD **и** ответы Telegram `ok=true` с `message_id`
  для всех частей отчёта. Это подтверждение API, а не прочтение пользователем.
- Доставленные части за текущие московские сутки повторно не отправляются.
  Неопределённый результат отправки/таймаут не повторяется автоматически:
  Telegram не предоставляет идемпотентный ключ, иначе возможны дубли.
- Явный отказ 429 допускает ограниченный повтор с учётом `retry_after`;
  сервис запускается повторно не более трёх раз за час. Остальные ошибки
  и неопределённые результаты требуют проверки оператором.
- Список названий встреч идёт только в разрешённый Telegram-чат. В журнале
  и состоянии нет названий, транскриптов, токенов или полного текста ошибок CLI.

Часовой `plaud-agent.timer`, выгрузка оценок в таблицу и старый монитор цен
`plaud-kontrol-ceny` **не изменяются**.

## Установка и переключение

1. Отправить только два monitor-скрипта, установщик и файлы из
   `ops/plaud-name-monitor` на сервер в отдельный каталог.
2. От root выполнить:
`python3 scripts/install-plaud-server-monitor.py --release <уникальная-версия> --preflight`.
   Установщик не включает таймеры и не отправляет отчёт. Он проверяет личность бота
   через `getMe`, использует существующий `/root/.plaud`, не копирует OAuth-токены.
3. Отключить старое расписание в GitHub; убедиться, что нет выполняющихся
   проверок того же workflow. Не затрагивать другие workflows.
4. `systemctl start plaud-name-monitor.service`. Проверить результат и `--status`.
   Если бот заблокирован или личный диалог не начат, владелец должен открыть
   `https://t.me/brokerStMichaelbot` и нажать «Начать»; без подтверждения доставки
   перенос нельзя считать проверенным.
5. Повторить запуск: число отправленных частей не должно увеличиться.
6. `systemctl enable --now plaud-name-monitor.timer plaud-name-monitor-watchdog.timer`.
   Проверить следующий запуск и запустить watchdog вручную после успешной проверки.
7. В основном репозитории workflow оставлен только для ручного аварийного запуска.
   Не запускать его после уже доставленного серверного отчёта за те же сутки:
   GitHub не разделяет серверный журнал идемпотентности.

## Контроль оператором

```sh
systemctl list-timers plaud-name-monitor.timer plaud-name-monitor-watchdog.timer
systemctl show plaud-name-monitor.service -p Result -p ExecMainStatus -p NRestarts
journalctl -u plaud-name-monitor.service -u plaud-name-monitor-watchdog.service -n 30 --no-pager
node /opt/plaud-name-monitor/current/monitor-plaud-server-runner.mjs --status
```

Перед обновлением остановить оба собственных таймера и сервиса: установщик
отказывается менять активный монитор. При ошибке проверки возвращает предыдущие
`current` и unit-файлы. Другие сервисы не останавливает.

Секреты: `/etc/plaud-name-monitor.env` (`root:root`, `600`), OAuth:
`/root/.plaud` (`700`, существующее общее хранилище CLI). Журнал состояния:
`/var/lib/plaud-name-monitor/state.json` (`600`). Sandbox скрывает остальной
домашний каталог root, запрещает запись за пределами собственного состояния
и профиля PLAUD. Код — неизменяемый выпуск `/opt/plaud-name-monitor/releases/<версия>`.

Контроль доставки хранит отдельный `state.json.watchdog.json` (`600`), чтобы
повреждение основного журнала не стирало защиту от повторных контрольных уведомлений.

Не удалять состояние для «повторного запуска»: это может повторно отправить отчёт.
При `UNKNOWN` сначала сверить доставку в самом боте и журнале. Откат: остановить
оба таймера, вернуть `current` на предыдущий выпуск из `previous-release`, проверить
конфигурацию и состояние; OAuth и журнал не стирать. GitHub-расписание возвращать
только после остановки серверных таймеров, чтобы не создавать два источника отправки.
