# Mango в кабинете брокера: инструкция администратора и колл-центра

Документ описывает действия в интерфейсе кабинета после production-деплоя и
успешной миграции. Он не содержит и не должен содержать реальные API key,
salt, пароли или телефоны клиентов.

## Что уже существует, а что нужно проверить

Mango не создаёт отдельного пользователя кабинета. Внутренний номер
`EmployeeNUM` привязывается к уже существующей карточке сотрудника.

Отдельные роли `CALL_CENTER_OPERATOR` и `CALL_CENTER_MANAGER` сейчас не
создаются. Используются роли кабинета:

| Роль | Возможности |
|---|---|
| `ADMIN` | Настройка Mango, назначение EmployeeNUM, распределение очереди, звонки и результаты |
| `MANAGER` | Работа со своей назначенной очередью, Mango-звонок и сохранение результата |
| `BROKER` | Раздел колл-центра и настройка Mango недоступны |

Наличие имён в `docs/call-center-team.md` не означает, что учётные записи уже
созданы в production. Перед включением администратор обязан найти каждую
карточку, проверить email, роль `MANAGER`, статус `ACTIVE` и возможность входа.
Не создавать дубль только потому, что сотрудник не найден с первой попытки:
сначала искать по email, телефону и ФИО.

## Часть 1. Первичная настройка администратором

### 1. Перевыпустить раскрытые реквизиты

Если API key или salt передавались в чате, письме или задаче, сначала отозвать
их в Mango и выпустить новые. Старые значения не использовать даже после
удаления сообщения.

Новые значения вводятся либо как GitHub Actions secrets, либо в защищённой
странице интеграций. Значение из базы (`SystemSetting`) имеет приоритет над
env, поэтому при ротации нужно обновить именно тот источник, который сейчас
показан активным.

### 2. Заполнить настройки в кабинете

1. Войти под пользователем с ролью `ADMIN`.
2. В левом меню открыть `Интеграции`.
3. Найти блоки Mango и сохранять каждое поле отдельной кнопкой `Сохранить`:

   - `Mango VPBX — уникальный код АТС` — новый `vpbx_api_key`;
   - `Mango VPBX — ключ для подписи` — новый `vpbx_api_salt`;
   - `Mango VPBX — API URL` — только
     `https://app.mango-office.ru/vpbx`;
   - `Mango — Callback URL` — оставить пустым при штатном подписанном VPBX
     callback; заполнять только для согласованного legacy integration-webhook;
   - `Mango — исходящая линия` — номер Caller ID из 10–15 цифр, например без
     пробелов, скобок и `+`.

4. После каждого сохранения дождаться зелёного сообщения. Секретные поля
   после сохранения остаются пустыми и показывают только факт наличия — это
   нормально. Не вставлять в пустое поле старую маску.
5. Не пробовать обходить проверку URL: HTTP, другой host, userinfo,
   нестандартный порт и redirect запрещены.

### 3. Зарегистрировать event webhook в Mango

В административном кабинете Mango открыть настройки API/уведомлений ВАТС и
зарегистрировать публичный HTTPS endpoint:

```text
https://broker.stmichael.ru/api/webhooks/mango/call-result
```

Нужны уведомления о состояниях звонка (`call_state`) с `call_id`,
`command_id`, `seq`, `from` и `to`. Точное название раздела Mango зависит от
тарифа и прав аккаунта; если меню API/уведомлений скрыто, это должен сделать
владелец ВАТС или поддержка Mango. Не подменять этот endpoint URL команды
`/commands/callback`: команда только запускает звонок, а итог приходит
отдельным событием.

### 4. Проверить или подготовить учётные записи сотрудников

Для каждого сотрудника:

1. Открыть `Админка — Брокеры`.
2. Искать сначала по рабочему email, затем по телефону и ФИО.
3. Открыть карточку и проверить, что это нужный UUID, а не однофамилец или
   импортированный дубль.
4. Проверить роль `MANAGER` и статус `ACTIVE`.
5. Если карточки нет, сотрудник сам открывает
   `https://broker.stmichael.ru/register`, регистрируется по своему рабочему
   телефону и задаёт пароль. Новая карточка получает безопасную роль `BROKER`.
6. После успешного входа ADMIN снова открывает карточку и меняет роль на
   `MANAGER`. Назначать `MANAGER` до установки пароля нельзя.
7. Если уже есть импортированная карточка `PENDING` с ролью `BROKER`, та же
   регистрация по совпадающему телефону активирует именно её, не создавая
   дубль. Сначала обязательно сверить телефон и ФИО.
8. Если найдена старая карточка `MANAGER`/`ADMIN` без пароля, публичная форма
   намеренно не активирует её. Не обходить защиту SQL-запросом: ADMIN должен
   подтвердить личность сотрудника, временно вернуть карточку в
   `BROKER` + `PENDING`, дать сотруднику завершить регистрацию и только потом
   снова назначить `MANAGER`.

### 5. Назначить EmployeeNUM

1. В карточке сотрудника найти поле `Mango EmployeeNUM`.
2. Ввести только цифры согласно таблице выше.
3. Нажать `Сохранить Mango`.
4. Убедиться, что появилось сообщение `Внутренний номер Mango сохранён`.
5. Обновить страницу и проверить, что номер сохранился.
6. Повторить для следующего сотрудника.

Один EmployeeNUM нельзя назначить двум карточкам. При конфликте не очищать
номер у случайно найденной записи: сначала сравнить UUID, ФИО, email и роль.
Чтобы отвязать номер, очистить поле и нажать `Сохранить Mango`.

## Часть 2. Работа администратора с очередью

1. Открыть `Колл-центр` в левом меню.
2. Использовать поиск и фильтры категории, специализации и координаторов.
3. Выбрать строки чекбоксами.
4. В панели назначения выбрать сотрудника и нажать `Назначить`.
5. Для отмены выбрать строки и нажать `Снять назначение`.
6. Проверить фильтр `Назначенные на меня`, `Без назначения` или `Все`.

Только `ADMIN` распределяет контакты. Оператор `MANAGER` получает и изменяет
только назначенные ему контакты.

## Часть 3. Ежедневная работа оператора колл-центра

1. Войти в кабинет под своей учётной записью `MANAGER`.
2. В левом меню открыть `Колл-центр`.
3. Оставить фильтр `Только мои`.
4. Найти нужного брокера и нажать кнопку звонка с иконкой телефона.
5. Кабинет отправит callback в Mango. Сначала Mango позвонит на внутренний
   номер оператора.
6. Взять трубку. После ответа Mango начнёт звонить брокеру и соединит стороны.
7. После разговора раскрыть карточку строки, выбрать результат, добавить
   комментарий и при необходимости дату следующего звонка.
8. Нажать кнопку сохранения результата. Строка должна исчезнуть из текущей
   очереди или получить новую дату согласно выбранному результату.

Не нажимать звонок повторно, пока идёт первый callback. UI и API ограничивают
повторный запуск, но оператор всё равно должен дождаться результата.

## Часть 4. Приёмочный тест перед массовыми звонками

Проводить на одном сотруднике и одном согласованном тестовом контакте:

1. Убедиться, что у сотрудника задан правильный EmployeeNUM.
2. Нажать звонок один раз.
3. Проверить, что сначала звонит внутренний номер сотрудника.
4. После ответа проверить соединение с тестовым контактом.
5. Убедиться, что исходящий Caller ID соответствует согласованной линии.
6. Завершить звонок и дождаться terminal webhook.
7. Проверить итоговый статус и отсутствие повторного/опоздавшего изменения.
8. Проверить журнал Mango/amoCRM для записи разговора, если запись включена
   на стороне Mango.

Только после успешного теста включать остальных операторов.

## Диагностика

| Сообщение/симптом | Действие |
|---|---|
| `У вас не заполнен внутренний номер Mango` | ADMIN открывает карточку сотрудника и задаёт EmployeeNUM |
| `Внутренний номер уже назначен` | Найти конфликтующую карточку; не менять данные по ФИО вслепую |
| `Доступ запрещён` | Проверить роль и статус; оператору нужна роль `MANAGER`, настройки доступны только `ADMIN` |
| Mango не звонит сотруднику | Проверить key/salt, EmployeeNUM, тариф/права VPBX и ответ команды callback |
| Сотруднику звонит, брокеру нет | Проверить телефон брокера, `doNotCall`, исходящую линию и правила Mango |
| Статус не обновляется | Проверить регистрацию event webhook, HTTPS, подпись и наличие `seq` |
| `401` от webhook | На сервере и в Mango используются разные key/salt либо старый secret после ротации |
| Двойной звонок | Не повторять кнопку; проверить throttling/idempotency и журнал вызовов |

## Что нельзя делать

- Не отправлять key/salt/token в чат и не сохранять их в git.
- Не назначать EmployeeNUM прямым SQL по ФИО.
- Не давать оператору роль `ADMIN` только ради доступа к колл-центру.
- Не запускать массовые звонки до одного полного теста callback + webhook.
- Не считать успешный ответ команды callback завершённым звонком.
