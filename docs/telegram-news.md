# Новости лендинга из Telegram-канала

С 29.09.2026 блок «Новости» на лендинге (`/v2` и старая главная) берёт посты
из закрытого Telegram-канала компании. Парсер сайта stmichael.ru остаётся
запасным источником: пока Telegram-новостей меньше четырёх, карточки сайта
дополняют блок; как только их четыре и больше — сайт не показывается.

## Как это устроено

- Бот кабинета (`@brokerStMichaelbot`, тот же, что читает ответы владельца в
  техподдержке) добавлен в канал администратором. Telegram присылает ему
  каждый новый и отредактированный пост канала.
- Опрос бота уже есть — `OpsInboxService` в api спрашивает Telegram
  (`getUpdates`) раз в 20 секунд. Он же отдаёт посты канала в
  `TelegramNewsService`, который сохраняет их в таблицу `landing_news`
  с источником `Telegram`. Отдельного webhook нет и ставить его нельзя: при
  webhook Telegram перестаёт отдавать `getUpdates` (ошибка 409), и ломается
  приём входящих техподдержки.
- Карточка новости: заголовок — первая строка поста (до 120 символов, без
  markdown), текст — весь пост, дата — дата поста, ссылка —
  `https://t.me/c/<id канала без -100>/<номер поста>`, обложка — самое большое
  фото поста, скачанное в хранилище `/files/news/telegram/…`. Альбом из
  нескольких фото — одна новость, обложкой идёт первое фото, подпись берётся
  с любого элемента альбома.
- Редактирование поста обновляет карточку. Удаление поста в канале не
  отслеживается — такую карточку выключают в админке (Новости → «активна»).

## Что нужно сделать владельцу

1. Открыть канал в Telegram → название канала → «Администраторы» →
   «Добавить администратора» → найти `@brokerStMichaelbot` → сохранить.
   Права можно оставить минимальные: для канала любое административное
   право даёт боту доступ к постам.
2. Опубликовать в канале любой пост (или отредактировать существующий).
   Бот видит только посты, вышедшие после его добавления; историю канала
   через бота получить нельзя.
3. Сообщить, что сделано, — дальше id канала снимаем инспектором (ниже) и
   вписываем в настройку.

## Как узнать id канала

У закрытого канала нет публичного имени, и ссылка-приглашение id не
содержит. После первого поста с ботом в канале id виден:

- в логах api: строка `[TelegramNews] TELEGRAM_NEWS_CHAT_ID не задан —
  принимаю канал chat.id=-100… title="…"`;
- через workflow **Inspect Telegram bot chats** (Actions → запустить вручную):
  печатает бота, наличие webhook, неподтверждённые апдейты и раздел «Что
  видел приём новостей (БД)» с последним увиденным каналом. Локально или на
  сервере то же самое: `docker compose exec -T api node
  /app/scripts/inspect-telegram-bot-chats.js`.

## Настройки

| Имя | Где | Назначение |
| --- | --- | --- |
| `OPS_TELEGRAM_BOT_TOKEN` / `TELEGRAM_BOT_TOKEN` | GH Secrets → `.env` | Токен бота, которого опрашивает api (уже настроены). Приоритет у `OPS_`. |
| `TELEGRAM_NEWS_CHAT_ID` | SystemSetting (workflow **Ops set system setting**, ключ `TELEGRAM_NEWS_CHAT_ID`) или env в `.env` сервера | Числовой id канала (`-100…`). Пока пусто — принимаются посты из любого канала, куда добавлен бот; после первого поста id нужно вписать, чтобы чужие каналы не попадали на сайт. Несколько id — через запятую. |
| `TELEGRAM_NEWS_LAST_CHAT` | SystemSetting, пишет api | Служебная: последний канал, увиденный приёмом (id, название, время). Руками не правится. |
| `TELEGRAM_API_BASE` | docker-compose | Ретранслятор Telegram API для контейнера (уже настроен). |

Миграция БД: `20260929120000_landing_news_telegram` — три колонки в
`landing_news` (`telegram_chat_id`, `telegram_message_id`, `media_group_id`),
существующие строки не меняются.

## Как проверить

1. После выкатки: workflow **Inspect Telegram bot chats** → бот отвечает на
   `getMe`, webhook пуст.
2. Владелец добавил бота и опубликовал пост → в течение минуты в логах api
   `[TelegramNews] новость создана: … ← -100…/<номер>`; инспектор показывает
   канал в разделе 4.
3. `GET /api/public/cms/news` отдаёт карточку с `source: "Telegram"` первой;
   на лендинге в подписи карточки `дата · Telegram`.
4. Вписать id через **Ops set system setting** (`TELEGRAM_NEWS_CHAT_ID`,
   значение `-100…`); настройка подхватывается без перезапуска (кэш 60 с).

## Ограничения

- Бот получает только новые посты после добавления в канал; старые посты в
  карточки не попадут.
- Ссылка `t.me/c/…` открывается только у участников закрытого канала. Если
  нужно, чтобы посетители сайта видели пост, канал должен быть публичным или
  у карточки нужна другая ссылка.
- Ссылку на файл Telegram публиковать нельзя (в ней токен бота, живёт ~час),
  поэтому если фото не скачалось, карточка остаётся без обложки; следующая
  правка поста повторит попытку.
- Видео, опросы, документы без текста в карточки не превращаются — только
  текст и фото.
