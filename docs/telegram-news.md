# Новости лендинга из Telegram-канала

С 29.09.2026 блок «Новости» на лендинге (`/v2` и старая главная) берёт посты
из закрытого Telegram-канала компании. С 30.09.2026 это единая лента:
Telegram-посты и карточки сайта stmichael.ru идут вместе по дате (свежие
выше, в один день Telegram первым), публичный `GET /api/public/cms/news`
отдаёт до 20 карточек (`?limit=1..20`, по умолчанию 20). Прежнее правило
«четыре Telegram-новости и сайт не показываем» отменено. Пост канала и новая
карточка с сайта попадают на лендинг только после согласования (раздел
«Согласование» ниже).

Лендинг `/v2` показывает первые 4 карточки ленты (так в макете), старая главная —
все в горизонтальной прокрутке. Парсер сайта снимает карточки с первой
страницы stmichael.ru/news (сейчас там 11; потолок 20); «Показать ещё» сайта
идёт через его внутренний API и не парсится, зато старые карточки из базы не
удаляются, поэтому лента со временем длиннее одной страницы.

## Как это устроено

- Бот кабинета (`@brokerStMichaelbot`, тот же, что читает ответы владельца в
  техподдержке) добавлен в канал администратором. Telegram присылает ему
  каждый новый и отредактированный пост канала.
- Опрос бота уже есть — `OpsInboxService` в api спрашивает Telegram
  (`getUpdates`) раз в 20 секунд. Он же отдаёт посты канала в
  `TelegramNewsService`, который сохраняет их в таблицу `landing_news`
  с источником `Telegram`. Отдельного webhook нет и ставить его нельзя: при
  webhook Telegram перестаёт отдавать `getUpdates` (ошибка 409), и ломается
  приём входящих техподдержки.
- Карточка новости: заголовок — первая строка поста (до 120 символов, без
  markdown), текст — весь пост, дата — дата поста, ссылка —
  `https://t.me/c/<id канала без -100>/<номер поста>`, обложка — самое большое
  фото поста, скачанное в хранилище `/files/news/telegram/…`. Альбом из
  нескольких фото — одна новость, обложкой идёт первое фото, подпись берётся
  с любого элемента альбома.
- Редактирование поста обновляет карточку (текст, обложку); статус
  согласования при этом не меняется. Удаление поста в канале не
  отслеживается — такую карточку выключают в админке (Новости → «активна»).

## Согласование

Новый пост канала сохраняется со статусом **«На согласовании»** (`PENDING`) и
на лендинг не попадает. Публичный endpoint отдаёт только `APPROVED`; всё, что
было в базе до 30.09 (сайт, ручные карточки), помечено `APPROVED` миграцией,
ручные карточки из админки тоже создаются сразу `APPROVED`.

**Новости с сайта** (решение владельца 30.09): парсер stmichael.ru/news
(крон 08:00 и кнопка «Синхронизировать с stmichael.ru» в админке) создаёт
новую карточку тоже `PENDING` и шлёт модераторам то же сообщение с кнопками —
заголовок, ссылка на новость на сайте, обложка (если есть) картинкой; анонса у
карточек сайта нет, поэтому текста под заголовком не будет. Существующие
карточки сайта парсер не переводит: при повторном парсинге обновляются только
заголовок/обложка/дата, статус остаётся каким был (`APPROVED` остаётся
`APPROVED`, скрытая — скрытой). Кнопки и обработка нажатий общие — по id
новости, источник не важен.

Как это выглядит у модераторов (владелец и Анна):

1. Бот присылает каждому сообщение «На согласование: новость для кабинета
   брокера» — заголовок, первые 300 символов поста (у новости сайта — без
   текста), ссылка на пост или на страницу сайта; если есть фото/обложка — оно
   идёт картинкой с этой подписью. Под сообщением две кнопки:
   **✅ Опубликовать** и **❌ Отклонить**.
2. Первое нажатие любого из модераторов решает: карточка становится
   `APPROVED` (появляется на лендинге) или `REJECTED`. Бот отвечает всплывашкой
   «Опубликовано»/«Отклонено», а в сообщениях **у обоих** модераторов убирает
   кнопки и дописывает «✅ Опубликовано: Имя» / «❌ Отклонено: Имя».
3. Повторное нажатие (в том числе вторым модератором) — всплывашка «Уже
   обработано». Чужие нажатия (не из списка модераторов) — «Нет прав на
   согласование», статус не меняется.
4. Если пост отредактировали, пока он ждал решения, текст в сообщениях
   модераторов обновляется, кнопки остаются.

То же самое доступно в админке **Лендинг → Новости**: фильтр по статусу
(«На согласовании / Опубликованные / Отклонённые»), бейдж статуса и метка
«Telegram» у карточки, у карточек «На согласовании» кнопки «Опубликовать» и
«Отклонить» (только ADMIN). Решение из админки тоже правит сообщения в боте.

В админке решение можно поменять (с 30.09): у опубликованной карточки кнопка
**«Скрыть»** (статус → «Отклонена», с лендинга уходит), у отклонённой/скрытой —
**«Опубликовать»** (→ «Опубликована»). В боте так нельзя: там первое нажатие
окончательное, повторное — «Уже обработано». Галочка «Показывать на лендинге»
по-прежнему работает как отдельный выключатель поверх статуса.

Разовое скрытие шести новостей сайта по решению владельца 30.09 («Детская
Академия падела», «Джазовый вечер…», «Время открытий…», «С Днем строителя!»,
«TURONE…», «Более 12 событий…») — workflow **Apply news hide**
(`.github/workflows/apply-news-hide.yml`, скрипт
`scripts/apply-news-hide-2026-09-30.js`): `mode=dry-run` печатает, что нашлось
по заголовкам, и прогоняет запись в транзакции с откатом; `mode=apply` +
`confirm_apply=true` ставит им `REJECTED` (строки не удаляются, вернуть можно
кнопкой «Опубликовать»). Остальные 14 остаются `APPROVED`.

Кому уходит «На согласование» и кто вправе нажимать — настройка
`TELEGRAM_NEWS_MODERATOR_CHAT_IDS` (список chat id через запятую):

- SystemSetting (workflow **Ops set system setting**) — главный источник,
  подхватывается без перезапуска (кэш 60 с);
- иначе env с тем же именем в `.env` сервера;
- иначе запасной вариант — чаты ops-алертов `OPS_ALERT_CHAT_IDS` /
  `OPS_ALERT_CHAT_ID` из `.env` (туда сейчас уходят алерты и заметки ops).

Chat id личного чата = user id человека в Telegram; узнать его можно из
таблицы входящих техподдержки (`ops_inbox_messages.chat_id` после любого
сообщения боту) или через workflow **Ops telegram chats info**. Чтобы бот мог
написать человеку первым, тот должен один раз отправить боту `/start`.
Если список пуст — уведомления никому не уходят (в логе api предупреждение),
новость ждёт решения в админке. Модераторов показывает инспектор
**Inspect Telegram bot chats** (раздел 4).

Технически: нажатия приходят тем же опросом `getUpdates` как `callback_query`
(`allowed_updates` дополнен), `callback_data` = `news:approve:<id>` /
`news:reject:<id>`; message_id уведомлений хранятся в `landing_news.moderation_notices`;
ответ на кнопку — `answerCallbackQuery`, правка сообщений — `editMessageText` /
`editMessageCaption` с пустой клавиатурой. Обложка новости сайта уходит в
`sendPhoto` https-ссылкой (Telegram скачивает сам; если не смог — сообщение
уходит текстом). Уведомление для сайта шлёт `TelegramNewsService.requestModeration`
из `CmsService.syncNewsFromStm`; ошибка Telegram синк не роняет — карточка
остаётся `PENDING` и ждёт решения в админке. Endpoint админки:
`POST /api/admin/cms/news/:id/moderate` `{ "status": "APPROVED" | "REJECTED" }`
(смена решения разрешена; тот же статус повторно → `result: "already"`),
`GET /api/admin/cms/news?status=PENDING`.

## Что нужно сделать владельцу

1. Открыть канал в Telegram → название канала → «Администраторы» →
   «Добавить администратора» → найти `@brokerStMichaelbot` → сохранить.
   Права можно оставить минимальные: для канала любое административное
   право даёт боту доступ к постам.
2. Опубликовать в канале любой пост (или отредактировать существующий).
   Бот видит только посты, вышедшие после его добавления; историю канала
   через бота получить нельзя.
3. Сообщить, что сделано, — дальше id канала снимаем инспектором (ниже) и
   вписываем в настройку.

## Как узнать id канала

У закрытого канала нет публичного имени, и ссылка-приглашение id не
содержит. После первого поста с ботом в канале id виден:

- в логах api: строка `[TelegramNews] TELEGRAM_NEWS_CHAT_ID не задан —
  принимаю канал chat.id=-100… title="…"`;
- через workflow **Inspect Telegram bot chats** (Actions → запустить вручную):
  печатает бота, наличие webhook, неподтверждённые апдейты и раздел «Что
  видел приём новостей (БД)» с последним увиденным каналом. Локально или на
  сервере то же самое: `docker compose exec -T api node
  /app/scripts/inspect-telegram-bot-chats.js`.

## Настройки

| Имя | Где | Назначение |
| --- | --- | --- |
| `OPS_TELEGRAM_BOT_TOKEN` / `TELEGRAM_BOT_TOKEN` | GH Secrets → `.env` | Токен бота, которого опрашивает api (уже настроены). Приоритет у `OPS_`. |
| `TELEGRAM_NEWS_CHAT_ID` | SystemSetting (workflow **Ops set system setting**, ключ `TELEGRAM_NEWS_CHAT_ID`) или env в `.env` сервера | Числовой id канала (`-100…`). Пока пусто — принимаются посты из любого канала, куда добавлен бот; после первого поста id нужно вписать, чтобы чужие каналы не попадали на сайт. Несколько id — через запятую. |
| `TELEGRAM_NEWS_LAST_CHAT` | SystemSetting, пишет api | Служебная: последний канал, увиденный приёмом (id, название, время). Руками не правится. |
| `TELEGRAM_NEWS_MODERATOR_CHAT_IDS` | SystemSetting (**Ops set system setting**) или env в `.env` сервера | Chat id модераторов новостей через запятую (владелец, Анна). Пусто → берутся `OPS_ALERT_CHAT_IDS`/`OPS_ALERT_CHAT_ID`; если и там пусто — уведомления не уходят, решение только в админке. |
| `TELEGRAM_API_BASE` | docker-compose | Ретранслятор Telegram API для контейнера (уже настроен). |

Миграции БД: `20260929120000_landing_news_telegram` — три колонки в
`landing_news` (`telegram_chat_id`, `telegram_message_id`, `media_group_id`);
`20260930120000_landing_news_moderation` — `moderation_status` (DEFAULT
`APPROVED`, существующие строки остаются на лендинге), `moderation_notices`,
`moderated_at`, `moderated_by`.

## Как проверить

1. После выкатки: workflow **Inspect Telegram bot chats** → бот отвечает на
   `getMe`, webhook пуст.
2. Владелец добавил бота и опубликовал пост → в течение минуты в логах api
   `[TelegramNews] новость создана: … ← -100…/<номер>`; инспектор показывает
   канал в разделе 4.
3. Владельцу и Анне приходит «На согласование …» с кнопками; после «✅
   Опубликовать» `GET /api/public/cms/news` отдаёт карточку с
   `source: "Telegram"` (до решения её в ответе нет); на лендинге в подписи
   карточки `дата · Telegram`. В админке карточка видна сразу со статусом.
   То же для сайта: после появления новой карточки на stmichael.ru/news и
   синка (08:00 или кнопка в админке) приходит «На согласование …» с обложкой
   и ссылкой на сайт, в логе api `[stm-news] новость создана (на согласовании)`.
4. Вписать id через **Ops set system setting** (`TELEGRAM_NEWS_CHAT_ID`,
   значение `-100…`); настройка подхватывается без перезапуска (кэш 60 с).

## Ограничения

- Бот получает только новые посты после добавления в канал; старые посты в
  карточки не попадут.
- Ссылка `t.me/c/…` открывается только у участников закрытого канала. Если
  нужно, чтобы посетители сайта видели пост, канал должен быть публичным или
  у карточки нужна другая ссылка.
- Ссылку на файл Telegram публиковать нельзя (в ней токен бота, живёт ~час),
  поэтому если фото не скачалось, карточка остаётся без обложки; следующая
  правка поста повторит попытку.
- Видео, опросы, документы без текста в карточки не превращаются — только
  текст и фото.
